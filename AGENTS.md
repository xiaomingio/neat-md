# Project entry points

- `src/extension.ts` registers the custom editor (default for `.md`, `.markdown`, `.mdown`) and the Open with Neat MD / Reopen as Text commands. Like Neat CSV, Neat MD owns the document: `MarkdownEditorProvider.ts` is a `CustomEditorProvider` (save, save as, revert, hot-exit backup) and stores the global view mode and language; `MarkdownFile.ts` holds the text (LF) and restores line endings and BOM on save; `MarkdownEditor.ts` connects one webview to one file.
- Undo: CodeMirror's history groups edits; each new group is reported as one VS Code edit, and VS Code's undo/redo replays it in the editor (`history` message). Keys, the corner buttons and native undo all go through VS Code so dirty state stays correct. Before save/backup the host asks the webview for the latest text (`requestText`). Close prompts come from VS Code. `configurationDefaults` sets `[markdown] files.autoSave` to `off` so closing asks to save; the settings dialog can let Markdown follow the general auto save setting instead.
- Five view modes: Live (default), Preview (Live rendering, read-only), Source, and the two split modes. The last chosen mode is remembered and applies to all editors.
- `src/markdown.ts` is the DOM-free renderer (markdown-it with footnotes, task lists, heading ids, TOC, `:::` containers, KaTeX math, Mermaid placeholders, highlight.js) used by the preview pane and Live widgets, and tested in Node.
- `src/webview/main.ts` owns the app shell: the top-right mode button and settings button, messaging, pasted-file insertion, preview scheduling and split scroll sync. The view mode and language are global: `MarkdownEditorProvider` stores them and broadcasts changes to every open editor. `controls.ts` holds the popup menu, mode menu and settings dialog. `editor.ts` builds one CodeMirror 6 editor shared by all four modes, with formatting shortcuts and image paste/drop. `livePreview.ts` implements Live mode as decorations: syntax is hidden unless the cursor touches it, block elements render as widgets until the cursor enters them, and list items use a hanging indent. Formulas, Mermaid and the TOC open on double-click by default (`neat-md.live.blockEdit`) and keep a live rendering under their source while edited. Block widget spacing must be padding on the `.md-block` wrapper, never margins: CodeMirror ignores margins when measuring widgets, which shifts every click below them. Tables are always interactive grids (`tableWidget.ts`, model in `src/table.ts`): a cell edit replaces only that cell's text, structural edits re-serialize the table, and the cursor never rests on table source unless "Edit as Markdown" was chosen. `preview.ts` renders the split-mode preview and reuses unchanged blocks. `rich.ts` sanitizes HTML with DOMPurify and renders Mermaid on demand. `i18n.ts` holds the Simplified Chinese strings.
- Pasted or dropped files are saved by the host into `neat-md.attachments.folder` (default `assets`, `${filename}` supported; helpers in `src/attachments.ts`) and linked relatively; images can be embedded as Base64. Rich-text paste is converted with `src/htmlToMarkdown.ts` (Turndown), which also maps rendered Neat MD output back to its syntax for copying from the preview.
- Saved files are plain Markdown. Live mode never changes text it does not edit; no metadata, attributes or private syntax is written.
- Mermaid (`dist/mermaid.min.js`) loads only when a diagram is first shown and renders with `securityLevel: 'strict'` and SVG labels. KaTeX CSS and woff2 fonts are copied to `dist/katex/` by `scripts/build.mjs`.
- English is the default for interface text, documentation, source comments and examples. Simplified Chinese is an optional interface language. Markdown content is never translated.
- After changes run `npm run typecheck`, `npm test`, and `npm run build`. UI changes also require `npm run test:ui`, using Chromium Headless Shell (`npx playwright install chromium --only-shell`). `tests/browser/harness.html` loads the built webview with a recording `acquireVsCodeApi` stub.
- `npm run package` writes a VSIX to `release/`. Debugging and automation must not start, display, focus, or activate desktop VS Code windows, extension hosts, or browsers. Install updates through the background CLI; let the user choose when to reload.
- Keep LICENSE, package metadata, and README license statements consistent with AGPL-3.0-only.
